Capabilities

Everything you'd expect — plus a hypervisor underneath

A familiar command surface backed by KVM-accelerated microVMs instead of shared-kernel namespaces.

🐳

Docker-like CLI

run, exec, attach, stop, rm — the verbs you already know, backed by full VMs.

📦

OCI image support

Pull from Docker Hub and any OCI-compatible registry, with digest verification and layer caching.

🛡️

Hardware isolation

Every VM boots a real Linux kernel with its own memory and network stack — stronger than a container.

⚡

Fast boot

MicroVMs start in 2–5 seconds thanks to Cloud Hypervisor's minimal device model.

🌐

Mycelium & TAP networking

Peer-to-peer IPv6 overlay with automatic IP tracking, or bridged TAP with NAT and port forwarding.

💾

virtiofs & block storage

Share host directories or back VMs with ext4 block devices — pick per VM.

🔌

Exec & attach over vsock

Run commands or drop into an interactive shell through a host↔guest vsock channel — no SSH required.

🧹

Self-healing cleanup

chvm doctor --gc reclaims leaked TAP devices, iptables rules, and orphaned processes from crashed VMs.

🔑

Registry auth & completions

chvm login/logout with ~/.docker/config.json, plus dynamic shell tab completion.

Quick Start

From clone to running VM

Build the host CLI and a statically-linked guest init, then boot your first microVM.

Clone & build

make build compiles the CLI and a musl-static guest init.

Check the host

chvm doctor verifies KVM, Cloud Hypervisor, virtiofsd and networking.

Set up

sudo chvm setup extracts a kernel and creates the bridge.

Run

chvm run nginx pulls the image and boots the VM.

install.sh 
# Clone the repo
$ git clone https://github.com/xmonader/chvm.git && cd chvm

# One-time: static musl target for the guest init
$ rustup target add x86_64-unknown-linux-musl

# Build host CLI + guest init, then install
$ make build && make install

# Prepare the host (kernel + bridge)
$ chvm doctor && sudo chvm setup

# Boot your first microVM
$ chvm run docker.io/library/alpine:latest
How it works

A thin, honest stack

  • OCI pull fetches and verifies image layers, then flattens them into a rootfs (honoring whiteouts).
  • Guest init — a static PID 1 written in Rust — mounts the rootfs, brings up networking, and reaps children.
  • Cloud Hypervisor boots a real kernel with the rootfs over virtiofs or an ext4 block device.
  • vsock channel carries exec and attach traffic between host and guest with binary-safe framing.
  • mycelium injects a peer-to-peer IPv6 overlay so VMs get routable addresses out of the box.
