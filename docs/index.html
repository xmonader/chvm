Capabilities

Everything you'd expect — plus a hypervisor underneath

A familiar command surface backed by KVM-accelerated microVMs instead of shared-kernel namespaces.

🐳

Docker-like CLI

run, exec, attach, stop, rm — the verbs you already know, backed by full VMs.

📦

OCI image support

Pull from Docker Hub and any OCI-compatible registry, with sha256 digest verification and layer caching.

🛡️

Hardware isolation

Every VM boots a real Linux kernel with its own memory and network stack — a stronger boundary than a container.

⚡

Fast boot

MicroVMs start in 2–5 seconds thanks to Cloud Hypervisor's minimal device model.

🌐

Mycelium & TAP networking

Peer-to-peer IPv6 overlay with automatic IP tracking, or bridged TAP with NAT and port forwarding.

💾

virtiofs & block storage

Share host directories or back VMs with ext4 block devices — chosen per VM.

🔌

Exec & attach over vsock

Run commands or drop into an interactive shell through a host↔guest vsock channel — no SSH required.

🧹

Self-healing cleanup

chvm doctor --gc reclaims leaked TAP devices, iptables rules, and orphaned processes from crashed VMs.

🔑

Registry auth & completions

chvm login/logout with ~/.docker/config.json, plus dynamic shell tab completion.

Why microVMs

The isolation of a VM, the ergonomics of a container

Containers share the host kernel; a shared kernel is a shared attack surface. chvm gives each workload its own kernel without giving up the container workflow.

Command reference

One CLI, the whole lifecycle

If you know Docker, you already know chvm. Reference VMs by name, full ID, or a unique ID prefix.

chvm run <image>

Pull an image and boot it as a microVM. --name, --cpus, --memory, -e KEY=VAL, -v host:guest, -p host:guest.

chvm ls

List VMs with state, resources, and network address. -a includes stopped VMs.

chvm exec <vm> <cmd>

Run a command inside a running VM over vsock and stream its output back, exit code intact.

chvm attach <vm>

Open an interactive shell inside the guest — no SSH, no open ports.

chvm stop <vm>

Gracefully shut the VMM down, then reclaim its TAP device and iptables rules.

chvm rm <vm>

Remove a VM and its rootfs. -f stops it first if still running.

chvm logs <vm>

Show the guest's serial console output for boot and runtime debugging.

chvm images

List locally cached OCI images and their digests. chvm login for private registries.

chvm doctor [--gc]

Check host prerequisites (KVM, hypervisor, virtiofsd); --gc reclaims leaked resources.

chvm setup

One-time host prep: extract a kernel and create the network bridge.

Networking & storage

Pluggable where it matters

Pick a networking mode and a storage backend per VM — defaults are sensible, overrides are one flag away.

🌐

mycelium

default
  • Peer-to-peer IPv6 overlay, end-to-end encrypted
  • Guest gets a routable address, no port mapping needed
  • Binary auto-injected into the guest, IP tracked on the host
🔗

tap

bridged
  • Bridged TAP device with NAT to the host network
  • Port forwarding via -p host:guest and DNS
  • Leaked devices & rules reclaimed by doctor --gc
📂

virtiofs

default
  • Rootfs and volumes shared straight from the host FS
  • No disk image to size or format — instant prep
  • Optional quota via default_virtiofs_quota_mb
🧱

block

ext4
  • Dedicated ext4 block device per VM
  • Sized with default_block_disk_size_mb
  • Stronger isolation of the guest's writable layer
Quick Start

From clone to running VM

Build the host CLI and a statically-linked guest init, then boot your first microVM.

Clone & build

make build compiles the CLI and a musl-static guest init.

Check the host

chvm doctor verifies KVM, Cloud Hypervisor, virtiofsd and networking.

Set up

sudo chvm setup extracts a kernel and creates the bridge.

Run

chvm run nginx pulls the image and boots the VM.

install.sh 
# Clone the repo
$ git clone https://github.com/xmonader/chvm.git && cd chvm

# One-time: static musl target for the guest init
$ rustup target add x86_64-unknown-linux-musl

# Build host CLI + guest init, then install
$ make build && make install

# Prepare the host (kernel + bridge)
$ chvm doctor && sudo chvm setup

# Boot your first microVM
$ chvm run docker.io/library/alpine:latest
How it works

A thin, honest stack

  • OCI pull fetches and sha256-verifies image layers, then flattens them into a rootfs (honoring whiteouts).
  • Guest init — a static PID 1 written in Rust — mounts the rootfs, brings up networking, and reaps children.
  • Cloud Hypervisor boots a real kernel with the rootfs over virtiofs or an ext4 block device.
  • vsock channel carries exec and attach traffic between host and guest with binary-safe framing.
  • mycelium injects a peer-to-peer IPv6 overlay so VMs get routable addresses out of the box.
